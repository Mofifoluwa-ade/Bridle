## 1. Service

Bridle is experimental testnet software for defining owner-signed spending mandates and allowing connected AI agents to inspect those mandates, check payment eligibility, submit proposals, and inspect proposal status and receipts.

The current deployment supports NEAR testnet native NEAR and Base Sepolia USDC. Solana is planned and is not currently executable. Bridle is not represented as a production mainnet payment service.

## 2. Testnet assets and transactions

Testnet assets have no promised monetary value. Blockchain transactions may be public, irreversible, delayed, or unavailable. A proposal marked cleared or ready is not necessarily an executed transfer. Users must verify execution using proposal status and a destination transaction receipt.

## 3. Agent permissions and owner responsibility

Owners are responsible for the mandates they create, the recipients and limits they approve, and the AI applications they authorize. An agent may submit proposals within the contract's rules. Agent tools do not provide owner controls to create, change, fund, revoke, veto, or flag mandates/payments.

Do not give an agent a credential or agent link unless you intend to authorize its use. Agent links and private keys must be kept secret. The hosted OAuth flow currently lacks per-app token revocation; this limitation must be resolved or prominently addressed before these terms are finalized.

## 4. No financial, legal, or tax advice
